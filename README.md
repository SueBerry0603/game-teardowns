## 每份拆解案长什么样

每个设计域都写三段，缺一段不算完成：

- **事实** —— 数值表 / 规则 / 配比，一条一行，**逐项标来源**。这段空着就是没拆。
- **拆解** —— 现象 → 机制 → 设计意图 → 代价与收益。机制必须落到数值或规则上，
  不写"这关太难"，写"该敌人有效血量 X、玩家期望输出 Y，需要 N 回合"。
- **判断** —— 一句**可被反驳的话**，带内部基准、外部对标，以及**边界与证伪条件**。

每份拆解案都以「它付出的代价」和「如果我来迭代」收尾，后者每条都要落到具体数值或规则上，
并写明代价。附录里是系统依赖图、数值细节、图表、数据来源与可信度、术语表。

## 数据从哪来

三档，正文逐项标注：

| 档 | 来源 | 要求 |
|---|---|---|
| 实测 | 本人游玩与访谈 | 标样本量 |
| 自陈 | 自我民族志、回溯自述 | 标 n=1，并写明回溯偏差 |
| 公开 | 官方数据库 / 反编译数据 | 标链接与版本 |
| 推断 | 期望、概率、比值 | **必须给算式** |

自陈与实测同形、可信度不同：正文里必须看得出哪句是「这是自述」、哪句是「这是行为证据」。

媒体文章的数字不采用——媒体不校数值，被追问一句就崩。
